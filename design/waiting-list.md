# 候診清單：設計說明

延伸第一階段（病人輸入症狀 → AI 評估 → 醫師查看）。第一階段的醫師頁只能輸入單一病人 ID 查看；這一階段改成醫師開頁就看到整個候診隊伍，點進去再看病歷與 CDS 卡片。

核心主張：**AI 負責排優先順序，醫師負責決定，系統留下可追溯的紀錄。**

## 1. 功能

| 功能 | 說明 |
|---|---|
| 候診清單 | 醫師頁開啟自動載入，每位病人一列，需人工介入者置頂 |
| 近期最高分 | 每位病人除了最新分數，另附最新一筆之前 24 小時內的最高分，避免「最新一句較輕」蓋掉剛剛的高分 |
| 點進明細 | 點清單中的病人，下方載入病歷與 CDS 卡片（沿用第一階段流程） |
| CDS 卡片 | 與清單共用同一套查詢；新增「近期曾有高分評估」警示卡 |
| 錯誤處理 | 後端或 FHIR 出錯時顯示錯誤，不顯示成「沒有病人」 |

## 2. 系統架構

見 `architecture.md`、`process.md`（架構圖）與 `process2.md`（時序圖）。重點是清單 API 與 CDS 共用 `services/triageResults.js`：

- `searchObservations`：查 FHIR（新舊代碼一起查、不用快取、分頁最多 200 筆）
- `flatten`：把 Observation 攤平成簡單資料，前端不必解析 FHIR
- `latestPerPatient`：每位病人只留最新一筆，並算出近期最高分

## 3. 清單 API

`GET /api/triage/results`，完整規格見 `triage-results-api.json`。

| 參數 | 用途 | 沒給時 |
|---|---|---|
| `patientId` | 只看某位病人 | 看全部病人 |
| `minScore` | 只看「近期最高分」≥ 此值（1–10） | 不篩選 |
| `limit` | 最多回幾位病人（1–50） | 20 |
| `sort` | `date`：時間新到舊；`score`：最新一筆需人工者在前，其次近期最高分，再其次時間 | `date` |

回傳：`success`、`count`、`truncated`（FHIR 還有資料沒抓到時為 true，清單可能不完整）、`items`。

每筆 item：`observationId`、`patientId`、`urgencyScore`、`needsHuman`、`emotion`、`symptoms`、`summary`、`assessedAt`、`recentMaxScore`。

錯誤規則：

- 參數不合法 → 400，附說明
- 查不到資料 → 200，`items` 為空陣列
- FHIR 連不上 → 502，**不可**回空陣列
- 分數不是 1–10 的整數 → `urgencyScore` 與 `recentMaxScore` 為 null、`needsHuman` 強制 true，不當成低風險

## 4. CDS 卡片規則

| 條件 | 卡片 |
|---|---|
| 最新分數 ≥ 5 | 🚨 高風險警示（≥ 8 為 critical，其餘 warning）；若近期曾更高，detail 多一行提示 |
| 最新 < 5，但近期最高 ≥ 5 | ⚠️ 近期曾有高分評估（warning），detail 同時列出高分那筆與最新一筆，轉介 Task 指向高分那筆 |
| 最新 < 5 且 AI 標記需人工介入 | ⚠️ AI 建議人工介入 |
| 其他 | ✅ AI 暫無高優先提示（低分不等於沒風險） |
| 查無紀錄 | ℹ️ 尚無 AI 分流紀錄 |
| 最新一筆分數無法判讀 | ⚠️ 資料無法判讀，請人工核對 |

| 2 | API 怎麼設計 | 每種查詢一支 API／一支 API 加參數 | 一支 API，用參數控制，函式盡量簡化 | 我提出 |
| 3 | 同一位病人列幾筆 | 全部紀錄／只留最新一筆 | 只留最新一筆 | AI 列選項，我選 |

| 6 | 最新低分但近期有高分時，CDS 卡片怎麼辦 | A 只加一行提示／B 升級成警示卡 | B：升級成警示卡並附轉介按鈕 | AI 列選項，我選 |

| 8 | 出錯與沒資料 | 兩者都回空清單／分開處理 | 分開：沒資料 200 空陣列，出錯 502 | 沿用第一階段原則 |

## 6. 驗證紀錄

每一步都在自己電腦用真實 FHIR（https://hapi.fhir.org/baseR4）驗證，並保存截圖。

| 步驟 | 驗證內容 | 結果 |
|---|---|---|
| 1 後端查詢 | 不給參數、`patientId`、不存在的病人（200 空陣列）、`limit` | 通過 |
| 2 整理與排序 | 每人一筆、`recentMaxScore`、`minScore`（含邊界）、`sort`、新病人立即出現、同一病人再送一筆會更新 | 通過 |
| 3 錯誤處理 | 7 種不合法參數回 400；故意改錯 FHIR 位址回 `success:false`，不是空陣列 | 通過 |
| 4 醫師頁 | 自動載入、點病人載入卡片、重新整理、窄視窗、後端關掉顯示錯誤 | 通過（樣式一度失效，已修正） |
| 5 CDS 共用 | 新警示卡內容正確；轉介 Task（472377）`priority=urgent`、`focus` 指向高分那筆；其他病人卡片與重構前一致；清單 API 輸出沒有多餘欄位 | 通過 |

另外用假資料做過重構前後的逐項比對：12 種 CDS 情境、13 種清單查詢，輸出完全一致。

## 7. 已知限制與未來延伸

- **沒有「已處置」狀態**：醫師處理過的病人不會離開清單，舊紀錄（例如三週前）會一直留著。下一個功能應該是醫師確認／已處置。
- **AI 每次只看單一句話**：不知道病人先前說過什麼，含蓄的句子可能被評成低分。目前靠「近期最高分」補救；之後可把近期紀錄一併交給 AI，或加關鍵字規則。
- **病人必須先存在於 FHIR**：病人端不能建立新病人。
- **清單最多 50 位**；FHIR 一次最多抓 200 筆（暫定值，超過會回 `truncated: true`）。
- **近期固定為 24 小時**；CDS 新警示卡固定為 warning，不會升到 critical。
- 其他可延伸方向：追問式問診、同一病人的分數趨勢、SMART on FHIR 登入。
